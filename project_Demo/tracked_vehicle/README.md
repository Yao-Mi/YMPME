# 逐节刚体履带车

这版按 `track_lab` 的物理装配方式重做整车：**两条履带各 28 节，每节都是刚体，用 28 个转动关节闭合成环。** 驱动轮通过接触摩擦带动履带，履带再与地面产生接触反力，推动整车。没有动画履带、履带相位推进、地面高度采样、虚拟牵引力，也没有下方支承块拖着车身走。

GRE 只读取刚体姿态显示。全部履带块的显示尺寸和碰撞盒一致；轮子与轮缘直接使用碰撞凸网格生成显示网格。窗口测试逐帧检查 56 节显示履带的顶点是否仍对应各自刚体的碰撞形状。

## 运行与操作

关闭旧窗口后，双击 `build/tracked_vehicle/demo_tracked_vehicle`。无外部模型资源、启动脚本或桌面入口。主工程构建对应目标时，输出在 `build/project_Demo/tracked_vehicle/demo_tracked_vehicle`。

| 操作 | 功能 |
|---|---|
| WASD / 方向键 | 驱动、后退、左右差速；左右键让两侧主动轮反向旋转 |
| B | 电机制动，需要电机开启 |
| 1 / 2 / 3 / 4 | 自由驾驶 / 斜撞墙 / 顺向凸起路面 / 横跨坡顶 |
| T | 自动持续前推；手动方向键和制动优先 |
| F | 地面摩擦系数 0.30 / 0；轮带摩擦保留，可观察履带空转 |
| M | 驱动电机开关，关闭后轮子和链条仍保持真实运动状态 |
| C / V / H | 视角 / 网格线 / 接触受力及铰链标记 |
| Space / N | 暂停 / 单物理步 |
| R / Esc | 重置当前场景 / 退出 |

快速检查：`2` 后按 `T` 看斜撞墙；`4` 看完整链条横跨黄色坡面。橙色标识每条履带的一节真实刚体，便于观察循环运动。黄条表示车头。

命令行支持 `--wall`（自动顶墙）、`--bumps`、`--crest`、`--smoke-test`。重置保留视角、显示及自动驾驶开关，并恢复物理参数。

## 物理组成

- 56 个履带刚体，每节 0.12 kg、节距约 0.134 m、宽 0.24 m、厚 0.028 m。碰撞长度为节距的 94%，铰链位于共同端点，留出链节转动空间。
- 每侧一套悬挂轮架：后主动轮、前从动轮、三个自由转动的承重轮。所有轮子统一为半径 0.14688 m，是上一版端轮的 1.2 倍；每侧两段各 10 节直线和两段各 4 节圆弧组成闭环。端轮中心距约 1.341 m，相邻轮中心距约 0.335 m，每侧履带链总长约 3.755 m。左右轮组中心距车身中线 0.635 m，轮缘内侧与车身侧面名义间隙约 13 mm，车身长度随轮距调整。承重轮通过与内侧履带的真实碰撞传递载荷，没有代替履带接地的滑块。
- 轮架通过竖向滑动关节和弹簧阻尼连接车身。每侧刚度 2000 N/m、阻尼 100 N·s/m，自由长度 0.35 m，压缩行程 0.16 m，下垂限位 0.03 m。两端弹簧力等大反向。
- 前从动轮装在纵向张紧滑架上：预载 160 N、刚度 350 N/m、阻尼 12 N·s/m，行程 −35～75 mm；这也是实际刚体和关节，不会覆写从动轮位置。
- 电机只作用在主动轮铰链上。最大力矩 60 N·m，按轮径将目标带速 ±0.67 m/s 换算为目标角速度，端轮最高约 ±4.56 rad/s，以约 12.25 rad/s² 斜坡启动，保持接近上一版的驾驶速度。初始化仅留 0.1 s 接触稳定时间，随后从零到目标转速约需 0.37 s，缩短启动和换向响应。其他轮子由履带接触带动。
- 轮子是沿轴向挤出的 12 边凸网格，轮缘与轮子属于同一个刚体，实际参与限位碰撞。轮带接触系数由履带 1.1、轮子 1.4 组合；轮缘为 0.15。地面默认 0.30，适合展示差速滑移和顶墙转向。库使用两形状摩擦系数的几何平均值。
- 整车共 82 个刚体（含 11 个固定地形刚体）、70 个关节、102 个碰撞形状。总质量 32.52 kg：车身 12 kg，其余为履带、轮组、轮架和张紧滑架。惯量用盒体或均匀圆柱近似，未做实车标定。

左右履带只能与各自轮组及外部地面/墙体接触，装配内部其他不必要的碰撞被过滤。与原 `track_lab` 一样，本 demo **过滤履带节之间的自碰撞**；铰链维持闭环，但不用于模拟链条折叠堆积、自碰撞或损坏。轮缘会限制轴向跑偏，不保证任意工况都不脱轨。

上方回程、下方接地段和端部弧段都是同一条物理链，不再存在独立的显示运动路径。驾驶室和车头色条只是固定在车身上的外观装饰。

## 反馈、性能与边界

面板显示主动轮实际转速及电机力矩、链节相对轮架的平均速率、地面支承力、墙面反力/力矩、张紧弹簧载荷、铰链误差及履带轴向偏移。平均链节速率是非负模长，前进/后退方向应看带符号的轴转速。绿色表示与地形接触受载的链节及接触力，黄色标识铰链。接触力来自求解冲量除以物理步长，含稳定化修正，瞬时数值会随接触切换波动。

物理为 240 Hz、48 次关节/接触迭代，使用接触和关节缓存。窗口每帧最多处理 8 个物理步，超载时丢弃追赶时间、放慢仿真，保持输入可响应。12 边轮子减少接触与绘制开销。窗口等待按本帧计算后的剩余预算设置，避免计算完成后再固定等待 16 ms；面板显示 FPS、仿真时间/现实时间比值和每帧物理耗时。相同前进回归（3.2 s 仿真）本机 Release 耗时从约 4.58 s 降至 1.51 s；一次实际 GRE 顶墙试跑末段约 33 FPS、仿真速度约 0.98 倍。这是本机测量，不保证实时 60 帧。

牵引、滑移、转向和爬坡都由接触求解决定。高摩擦、有限电机力矩或高台阶可能让车卡住，不能保证自动贴墙或一定爬过。没有齿形啮合、柔性履带、土壤变形；轮子是有限面数的凸多边形，法向响应包含几何棱边效应。

该带关节凸形车辆未启用库内针对独立球体的 CCD，采用离散检测。mesh/定向盒碰撞并不保证绝对零穿透；需要结合步长、求解迭代、接触和关节误差评估。修复的是履带显示与物理脱节，不是宣称任何速度下都零误差。

## 构建与验证

从仓库根目录独立构建：

```console
cmake -S project_Demo/tracked_vehicle -B build/tracked_vehicle -DCMAKE_BUILD_TYPE=Release -DYMPME_GRE_ROOT=/home/yaomi/文档/0502_YMGRE
cmake --build build/tracked_vehicle --target demo_tracked_vehicle test_tracked_vehicle -j 4
ctest --test-dir build/tracked_vehicle --output-on-failure -j 2
```

纯物理构建用 `-DTRACKED_WINDOW=OFF`，不依赖 GRE 或传感器；物理部分复用 RIGID、JOINT、DYNAMICS、SUSPENSION。主工程启用 DYNAMICS 和 SUSPENSION 后，也会注册测试或 GRE demo 目标。

物理回归分别检查前进、倒车、真实链节循环、电机关闭、差速转向、斜撞墙、横跨坡顶后转向，以及零地面摩擦时履带仍循环而整车质心水平位置保持不变。地形测试检查所有链节的碰撞顶点及真实接触，非仅检查少量支承点。

本次 Release 回归中，最大关节误差约 5.27 mm，最大接触穿透约 9.39 mm；坡顶场景检查到履带顶点侵入约 8.64 mm。这些数值仅代表固定测试场景，不是任意工况的上限。

GRE 离屏测试检查输入、暂停/单步、摩擦/电机开关、重置、场景切换、渲染变化，以及所有显示履带是否匹配物理碰撞盒。`YMPME_TRACKED_CAPTURE` 可给离屏测试指定 PPM 截图前缀。旧 `track_lab` 台架和其他车辆 demo 未修改。
