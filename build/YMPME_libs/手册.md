# YMPME 独立库使用手册

## 默认配套交付（0.3.x）

`python3 sdk/build.py` 生成 16/32 位两份全功能一体库，分别为 libympme_index16.a、libympme_index32.a。包默认选 16 位；通过 YMPME_INDEX_BITS 选择，所有索引数组使用 PME_Index。共享 GRE 数据时双方位宽必须一致。

使用 YMPME::ympme 和 YMPME.h 即可，模块目标名作为兼容别名保留。原分模块脚本为 build_modular.py。共享几何、原生绑定和释放顺序详见 docs/SHARED_MESH.md。以下裁剪说明适用于分模块包。

## 分模块接口与裁剪

下表描述源码及分模块包的模块职责。一体包中所有这些目标都是同一完整静态库的兼容入口，链接 `YMPME::ympme` 即可，不能通过改目标名裁剪一体包。

| 目标（均以 `YMPME::` 开头） | 用途 / 主要依赖 |
|---|---|
| `ympme` | 基础物体、世界、碰撞与求解，依赖系统数学库 |
| `rigid`、`joint`、`dynamics` | 三维刚体、关节、统一接触求解；后者逐级依赖前者 |
| `query` | 世界射线求交 |
| `drive`、`terrain`、`suspension`、`vehicle` | 驱动、地形、悬挂、车辆；vehicle 依赖前三者 |
| `gear`、`belt`、`pulley`、`rope` | 齿轮、皮带、滑轮、离散绳模型 |
| `flight`、`aircraft` | 飞行载荷及飞行器模型；aircraft 依赖含旋翼和气动的 flight |
| `pendulum` | 关节摆模型，依赖 joint |
| `surface_atlas`、`skin_contact`、`softbody` | 表面图谱、皮肤接触、局部柔性材料，分别独立选择 |
| `sensor` | 采样与信号公共层 |
| `imu`、`encoder`、`force_sensor` | 惯性、角度编码、力传感器 |
| `laser`、`lidar`、`depth`、`tactile` | 单点激光、雷达、深度、触觉；内部依赖 sensor_geometry |

`YMPME_AVAILABLE_COMPONENTS` 返回当前包的实际模块。可用 `find_package(YMPME CONFIG REQUIRED COMPONENTS dynamics encoder)` 让缺失模块在配置阶段明确报错。对分模块包，只有链接选中的目标才会传递其宏和依赖；对一体包，链接任一兼容目标都会传递全部功能配置。不要额外手动启用不存在的模块宏。

分模块包中每个模块单独保存为静态库，最终程序只链接需要的模块。若交付包本身也要变小，在源码中用 `python3 sdk/build_modular.py --profile core --output build/YMPME_core_libs` 生成仅核心包。自定义裁剪可直接使用原有 `YMPME_ENABLE_*`、`YMPME_MODEL_*`、`YMPME_SENSOR_*` CMake 开关，额外设置 `YMPME_INSTALL_SDK=ON`，构建后 `cmake --install 构建目录 --prefix 目标目录`。只导出该构建实际存在的模块；安装请使用新目录，避免残留旧模块。

## 六个示例

- `demo_sdk_minimal.c`：调用方提供物体内存，固定步长自由落体，对末态做基本检查；分模块包中编译时确认可选模块未启用，一体化包则使用完整接口配置。
- `demo_sdk_dynamics.c`：球体落到平面上并静止，直接读取接触反力；分模块包链接 dynamics，一体包只链接 ympme；都不需要创建 skin 或传感器对象。
- `demo_sdk_encoder.c`：0～360° 对应 uint16 的 65536 个码值，360° 回绕到 0。`now` 和 `last` 均为 uint16，使用 `int16_t delta = (int16_t)(now - last)`。累加器用更宽有符号类型，采样间运动须小于半圈，否则方向无法唯一确定。

- `demo_sdk_mesh_indices.c`：连续数组与借用网格的碰撞、索引边界；存在相应模块时也验证射线、动力学和 CCD。
- `demo_sdk_shared_gre.c`：借用真实 GRE 顶点和逐面索引，软件渲染后再次碰撞检测，检查源数据未改变；仅重编此项需要外部 GRE SDK。

- `demo_sdk_debug.c`：日志回调、等级过滤、参数错误后恢复、运行时静音；不触发致命断言。

一体包可执行文件位于 `bin/index16/` 和 `bin/index32/`，六个示例均为终端自检，没有交互窗口。分模块包使用 `bin/`，默认构建的示例随模块变化；核心包包含 minimal、mesh_indices 和 debug 三项。

在发布包根目录重编纯物理示例：

```console
cmake -S examples -B examples-build16 -DYMPME_INDEX_BITS=16
cmake --build examples-build16
ctest --test-dir examples-build16 --output-on-failure
```

加入 GRE 共享验证时，在配置命令追加 `-DYMPME_SDK_WITH_GRE=ON -DYMGRE_DIR=/absolute/path/YMGRE_libs/cmake`。32 位使用另一个构建目录并指定 `-DYMPME_INDEX_BITS=32`；GRE 示例自动选择相同位宽。

## 日志诊断

0.3.1 起默认将 WARNING/ERROR 输出至 stderr，记录错误码、原因及源文件/函数/行号，普通日志不会退出程序。`YMPME_Debug_SetLogger` 可改接应用回调或静音；`YMPME_Debug_ResetLogger` 恢复默认。日志、stderr 输出与断言分别可在编译时配置，断言默认关闭；预编译包的配置不能通过应用端单独定义宏改变。完整接口、线程和实时性约定见 [DEBUG 说明](docs/DEBUG.md)。

## 调用和资源约定

以米、秒、千克、弧度为基本单位。场景示例采用 +Y 向上、+Z 向前、+X 向右；应用应统一坐标约定。物理固定步长与渲染帧率分开，接触和关节稳定性取决于步长、迭代数、形状大小与质量比。

基础世界与统一 DYNAMICS 是不同接口；不要直接互换 `pme_body` 和 `pme_rigid_body`。使用与目标对应的公开头文件及数据结构。示例展示的数组由调用方持有，必须在仿真世界使用期间有效；容量不足应检查返回值，不应忽略失败继续读取输出。

接触反力是求解反馈，可直接供控制器读取。传感器模块用于采样、安装变换、噪声或编码等额外需求；不是每个物体都必须挂传感器，更无需普遍挂 skin。

## 与 GRE / SKE 对接

物理包不包含 GRE、SDL、YMSKE 或窗口宿主，加载和运行物理无图形依赖。应用分别链接物理与渲染库，把物体位置和姿态同步给 GRE，显示与碰撞形状由应用维持一致；接触、速度、姿态反馈直接从 PME 数据结构读取。骨骼动画由 SKE 驱动或读取物理姿态，PME 不承担蒙皮渲染。

本包附带 `examples/gre/YMPME_GREMesh.h` 和 `.c`，由应用与选定的 GRE 一起编译；物理静态库本身不引用 GRE。`YMPME_GRE_Mesh_Bind` 直接借用 GRE 的局部顶点与每面索引，`YMPME_GRE_Mesh_PrepareRender` 把姿态写入 GRE 已有的工作顶点。两者共用原始几何，但碰撞轴缓存、显示面片记录和渲染工作区仍需保留。

绑定只支持单个闭合凸三角网格；源对象的顶点、索引、拓扑及 scale 在使用期间不可修改或释放。不要对源对象调用 LocalToWorld，也不要用 GRE 的对象释放函数释放借用的 render 壳。先移除物理和渲染引用，再 Unbind，最后释放源对象及调用方缓存。通用 `pme_mesh_view` 不含 GRE 类型，其他渲染器也可使用。

详细布局、接口与限制见 [共享网格说明](docs/SHARED_MESH.md)。这次未把旧 Demo 全部迁移到共享路径；附带共享示例展示新接法。

## 兼容性与验证

当前包为 0.3.x；网格结构新增共享视图，0.2.x 消费者须使用新头文件重新编译。一个程序只能选择一种 PME 索引位宽；共享 GRE 几何时双方必须一致。二进制架构、编译器、构建开关和源码摘要见 `BUILD_INFO.json`。完整包默认 Release、位置无关静态库。头文件和库必须成套升级；开发阶段版本号相同也不代表不同源码快照二进制兼容，应核对构建信息。

`verification/` 包含把 SDK 拷贝到新路径后，仅用包内头文件、库和示例构建/运行的记录，以及所有导出模块的完整链接检查。`sha256sum -c checksums.sha256` 验证本次交付文件；用户修改或重新编译包内文件后校验结果会相应变化。
